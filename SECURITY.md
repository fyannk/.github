# Security Policy

## Supported versions

Unless a project states otherwise, security fixes are provided for the latest
published release only. Projects before 1.0 receive fixes on their most recent
0.x minor, without backports.

## Reporting a vulnerability

Please do not open a public issue for a suspected vulnerability.

Use **GitHub private vulnerability reporting** on the affected repository:
open its **Security** tab and choose **Report a vulnerability**. The report and
any supporting material stay confidential between you and the maintainer.

Please include:

- the affected project and version or commit,
- the deployment configuration,
- the impact you observed or expect,
- reproduction steps,
- a suggested mitigation, if you have one.

Never include live credentials, tokens, customer data, or other secrets in a
report.

## Disclosure

Public disclosure should wait until a fix or mitigation is available and a
coordinated disclosure date has been agreed. I aim to acknowledge reports
within a week.
